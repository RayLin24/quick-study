# 使用交互式文档执行端到端测试

## 目标

在本章中，我们将利用 FastAPI 自动生成的交互式 API 文档（Swagger UI）对上一章创建的 GET 接口进行一轮端到端测试。我们将学习如何打开文档、调用接口、核对响应状态码与响应体，并讨论判断测试通过的标准。

## 前置条件

- 已按照上一章创建 FastAPI 应用，并定义了一个 GET 接口。
- 已安装 FastAPI 和 Uvicorn。
- 应用可在本地启动。

## 打开交互式 API 文档

FastAPI 会自动为您的应用生成交互式 API 文档。根据 [FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/first-steps/)（以下称“教程”），您可以通过访问 `http://127.0.0.1:8000/docs` 打开 Swagger UI，通过 `http://127.0.0.1:8000/redoc` 打开 ReDoc。这两种文档都基于 OpenAPI 规范，展示了应用中所有已定义的路径操作、请求参数、请求体和响应模型。

教程中给出的启动命令是：

```bash
uvicorn main:app --reload
```

启动后，在浏览器中打开 `http://127.0.0.1:8000/docs`。

## 在文档中找到目标 GET 接口

Swagger UI 页面按路径（Paths）分组列出所有接口。假设上一章创建的 GET 接口的路径为 `/`（示例），您会看到 `GET /` 这样的条目。点击该条目可以展开其详情，包括接口描述、参数、请求体和响应格式。

（教学抽象：如果您上一章创建的 GET 接口路径不同，请在文档中找到对应的路径名。）

## 使用“Try it out”调用接口

Swagger UI 为每个接口提供了“Try it out”按钮。点击该按钮后，按钮会变为“Execute”。这一功能允许直接在当前浏览器中向您的应用发送实际 HTTP 请求。

操作步骤如下：

1. 在展开的接口详情中，点击 **Try it out**。
2. 如果接口需要路径参数、查询参数或请求体，请在相应的输入框中填入测试数据。例如，若接口为 `GET /items/{item_id}`，您需要填写 `item_id` 的值。
3. 点击 **Execute** 按钮。Swagger UI 将向实际运行中的 FastAPI 应用发送请求。

（教学抽象：“Try it out”按钮是 Swagger UI 的标准功能，教程并未详细描述其用法，但您可以在打开的文档页面中看到并操作。）

## 核对响应内容与状态码

执行后，Swagger UI 会显示以下信息：

- **Request URL**：实际发送的请求地址。
- **Response body**：服务器返回的响应体。
- **Response headers**：响应头。
- **Code**：HTTP 状态码。

这些信息正是端到端测试中所需要比对的“实际输出”。例如，若您的 GET 接口被设计为返回 `{"message": "Hello World"}`，则期望的响应体应为：

```json
{"message": "Hello World"}
```

期望的状态码通常为 `200 OK`。

### 核对清单

（以下核对项为常规测试方法的教学抽象，并非教程原文。）

- **状态码**：确认返回的 `Code` 是否为预期值（如 `200`）。若为 `404`，则可能路径错误或资源不存在；若为 `500`，则服务器内部出现异常。
- **响应体**：逐字段检查响应体是否符合预期。字段名、字段类型和取值都应核对。
- **响应头**：确认 `Content-Type` 是否为 `application/json` 等预期类型（如果接口返回 JSON 的话）。

## 判断测试通过的标准

一个端到端测试用例通过，通常需要同时满足以下条件：

1. 请求成功完成，没有网络连接错误、超时或浏览器层面错误。
2. 返回的 HTTP 状态码与接口规范中声明的状态码一致（一般为 2xx）。
3. 响应体内容与接口定义（OpenAPI schema）或业务预期完全匹配。
4. （可选）响应时间在可接受的性能阈值内。

（教学抽象：上述四条标准是常规软件工程中端到端测试的常见定义，FastAPI 官方教程并未讨论“测试通过标准”这一概念。在您的实际项目中，请根据业务需求调整标准。）

## 使用 ReDoc 作为参考

教程中还提到您可以通过 `http://127.0.0.1:8000/redoc` 访问 ReDoc。ReDoc 以更友好的阅读布局展示同一个 OpenAPI 文档，但通常不提供执行请求的功能（教学抽象：这一点并非教程原文，而是 ReDoc 的常见行为）。因此，您可以在 ReDoc 中仔细核对接口的请求/响应结构，然后在 Swagger UI 中实际执行测试。

在本章中，我们利用 FastAPI 自动生成的交互式文档，对上一章的 GET 接口进行了一次真实的端到端调用，并核对了响应状态码和响应体。同时我们给出了测试通过的判定标准。下一章，我们将把这套手工流程自动化，编写真正的自动化测试脚本。
