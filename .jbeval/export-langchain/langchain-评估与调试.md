# 评估与调试

在构建基于大语言模型（LLM）的链（Chain）和代理（Agent）时，评估与调试是不可或缺的环节。它们帮助你理解系统的行为、量化输出质量，并快速定位异常。

## 追踪链和代理的运行过程

追踪（Tracing）是记录一次完整调用的内部步骤、输入、输出及其时序的过程。在 LangChain 中，链和代理的执行通常涉及多个模型调用、工具调用和中间计算。通过追踪，你可以：

- 查看每一步使用的提示词和模型参数。
- 观察工具调用的参数与返回值。
- 测量每一步的耗时和 token 消耗。

**教学抽象**：下面的伪代码展示了一个通用追踪框架的结构，并非特定 LangChain API 的真实签名。

```python
with tracer.start_trace() as trace:
    result = agent_chain.run("你的问题")
    trace.print()  # 输出完整的调用树
```

在上面的抽象中，`tracer` 负责收集所有子步骤的信息，并在结束后展示调用树。真实实现中，LangChain 可能通过回调或中间件来完成类似工作。

## 评估生成结果的准确性

评估（Evaluation）通常基于一组测试样例，每个样例包含输入和期望输出。你可以定义多种指标来度量生成结果：

- **精确匹配**：结果是否与期望输出完全一致。
- **语义相似度**：使用嵌入模型计算结果与期望输出的向量距离。
- **LLM 作为裁判**：让另一个 LLM 根据评分标准给结果打分。

**教学抽象**：以下代码展示了一个评估流程的通用形式。

```python
test_case = {"input": "北京的天气如何？", "expected": "北京今天晴。"}
output = chain.run(test_case["input"])
score = evaluate(output, test_case["expected"])
print(f"评分: {score}")
```

这里的 `evaluate` 函数可以是任何指标的实现。由于本教程无法验证 LangChain 中具体的评估 API，建议参考官方仓库的最新文档。

## 利用追踪信息定位问题

当输出结果不符合预期时，追踪信息是关键的诊断工具。常见问题包括：

- 工具返回了错误格式的数据。
- 检索器（Retriever）召回了不相关的内容。
- 模型在某个步骤生成了错误的格式化输出。

通过查看追踪中的每一步输入/输出，你可以快速定位到失败节点。例如，如果追踪显示一个工具调用的输入参数为空，那么问题可能在参数构造环节。

## 实践建议

1. 在开发阶段始终开启追踪，并保存每次运行的追踪 ID。
2. 为链和代理建立一套回归测试集，每次修改后运行评估。
3. 将评估指标分为客观指标（如准确率）和主观指标（如可读性），用于不同的场景。
4. 如果追踪信息不足，尝试在关键节点增加日志输出。
